# PDF 和图片文档解析

## 用户故事

- 作为一个需要从几十页 PDF 里提取文字和表格的研究员，我希望丢进去文件直接拿到 Markdown，而不是一行行复制粘贴再排版。
- 作为一个处理扫描件合同的人，我希望哪怕 PDF 是图片扫描的，也能把里面的文字和表格结构准确提出来。
- 作为一个有中英文混排需求的人，我希望一行里同时有中英文、数学公式、表格时别把公式当成乱码或者把表格拆散。
- 作为一个对速度有要求的人，我希望纯文本文档能秒出结果，不用等模型慢慢推理。

## 为什么需要

把 PDF 变成能直接用的文本，这件事做了几十年，多数工具还是处理不了混合内容——文本文档能提文字但公式丢了、OCR 能提文字但表格散了、AI 模型能理解复杂页面但慢得用不了。一场产品发布会 PDF 里面可能同时有海报图片、数据表格、技术公式、多语言混排，这些工具要么只认一种，要么各管各拼不起来。

## 怎么解决

用多后端策略覆盖不同精度和速度需求。本地传统模型（布局检测 + OCR + 公式识别）处理常规文档够快；视觉语言大模型逐页理解复杂页面但更慢；两个连起来用就拿到两种好处。最终统一输出 Markdown 或结构化 JSON，排版、公式、表格、图片引用都在原位。

## 边界

- 只管 PDF 和常见图片格式（PNG/JPEG/WebP/BMP/TIFF），不管 Office 文档（走 Office 文档解析）。
- 速度最快的 pipeline 后端需要提前下载模型文件（约 2GB），或接受首次运行时自动下载。
- 精度最高的 VLM 后端需要 GPU 和不少显存（1.2B 模型约 3GB，7B 更大），纯 CPU 不可用。
- 单页独立解析，不处理跨页的文档级语义（如"续上页表格标题"）。跨页表格合并在部分场景支持但不保证完美。
- 不保证扫描件手写体识别、不保证重度污损文档、不保证复杂 PDF 表单字段。
