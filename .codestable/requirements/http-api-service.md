# HTTP API 解析服务

## 用户故事

- 作为一个后端开发，我希望直接调接口传文件拿到解析结果，而不是每次都在命令行里跑一遍、脚本嵌入还得管理进程。
- 作为一个做 SaaS 集成的人，我希望有一个标准的 HTTP 上传接口，把文档解析嵌到自己的业务流程里。
- 作为一个一次要处理多份文件的人，我希望并发上传多份文件，服务自己排队处理而不是我写并发逻辑。

## 为什么需要

命令行工具适合自己本地用，但一涉及集成就麻烦了——要管理进程生命周期、自己写并发调度、处理超时和错误。把解析能力封装成 HTTP 服务，任何语言都能用，和现有系统对接成本最低。

## 怎么解决

启动一个本地 HTTP 服务（默认只监听 `127.0.0.1`），暴露文件上传接口。接收 PDF/图片/Office 文件，内部复用命令行工具的后端解析逻辑，完成返回 Markdown 和 JSON 结果。支持同步等待和后台任务两种模式，自带并发控制和超时管理。

## 边界

- 默认只绑定本地回环地址，不直接对外开放。有公网部署需要时需显式配置绑定地址和安全策略。
- 不负责鉴权和用户体系——这是上层业务的事。
- 并发上限可配置，超出上限的请求排队或拒绝，不无限堆积。
- 大文件（几百页 PDF）解析耗时长，需要考虑客户端超时设置。
- VLM 后端模式下首次启动需要加载模型（秒到分钟级），冷启动请求会慢。
